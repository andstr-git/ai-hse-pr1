# Отчет

## 1. Представление

Инструмент один раз обходит каждый `.py`-файл внутри каталога, указанного через `--root`, и складывает результат в три таблицы: символы, импорты и места вызовов. Синтаксический разбор делает Tree-sitter, сам анализ – наш код обхода.

Символ – это класс, функция или метод (включая вложенные и `async`) с полным именем от корневого пакета: `fastapi.applications.FastAPI.openapi`. У символа хранятся вид (`module`/`class`/`function`/`method`), файл относительно родителя `--root`, строка определения (строка `def`/`class`) и пометка `async` – синхронность метода. Файл `fastapi/openapi/utils.py` становится модулем `fastapi.openapi.utils`. Одно видимое имя может быть определено дважды – в двух ветках `if` хранятся оба варианта, потому что оба могут быть активны.

Отдельно хранится каждое место вызова: выражение (`run_helper`, `b.Formatter`, `dependant.call`), файл, строка, охватывающий объект – ближайшая функция или метод, если их нет – класс, иначе модуль, и результат разбора: `internal` (цель внутри проекта), `external` (вне него, например `json.dumps`), `unresolved` (определить нельзя, с причиной). Индекс FastAPI состоит из 48 модулей, 550 символов, 3541 вызова, строится за ~0.5 секунды.

## 2. Разрешение имен

Имя вызова ищется по видимости: сначала в теле текущей функции или метода, затем в модуле. Тело класса из метода не видно – так устроен Python. Для импорта имя превращается в путь: модуль -> его подмодуль -> определение -> ре-экспорт в `__init__.py` (и снова по цепочке). Правила, по
одному примеру на каждое, все проверены тестами (`tests/test_resolution.py`):
- имя из того же модуля: `_helper(value)` -> `rules_pkg.mod._helper`
- вложенная функция: `nested_inner()` внутри `nested_outer` -> `rules_pkg.mod.nested_outer.nested_inner`
- импорт с локальным именем и относительный: `run_helper()` (при `from .b import helper as run_helper`) -> `tiny_pkg.b.helper`
- импорт модуля и атрибут: после `from . import b` вызов `b.helper()` -> `tiny_pkg.b.helper`; после `import pkg.b` вызов `pkg.b.helper()` -> `pkg.b.helper`
- ре-экспорт цепочкой: `fastapi.FastAPI` -> класс в `fastapi/applications.py`
- вызов класса: `b.Formatter()` -> собственно класс, не `__init__`
- `self._wrap(x)` в методе -> `tiny_pkg.b.Formatter._wrap`
- перекрытие: `def wrapper(target): target()` – не модульная функция, а `unresolved`: параметр затеняет внешнее имя

Неразрешенное показывается как `unresolved` с описанием проблемы.

## 3. Ограничение
*Реальный вызов из FastAPI, оставшийся неразрашенным*
```
uv run repo-map callees fastapi.routing.run_endpoint_function --root ../fastapi/fastapi
```

`fastapi/routing.py:352: return await dependant.call(**values)`. `dependant` – параметр функции, объект описания зависимости; какая именно функция в нем лежит, выясняется при сборке обработчика маршрута в `APIRouter.add_api_route` и в строке 352 не видна. Для точного ответа нужен межпроцедурный анализ потока данных и вывод типов. Инструмент отвечает `unresolved` с причиной `dynamic receiver`: ложное уверенное ребро хуже честного `unresolved`.

## 4. Использование AI

Код обхода дерева, разрешение имен, граф вызовов и тесты написаны coding-агентом (OpenCode) по пунктам задания. Я настроил первичное окружение, проверял каждый шаг прогоном команд и читал код ключевых мест. 
Пойманные ошибки: 
* охватывающий объект вызова сначала брался внешний (модуль) вместо внутреннего, и `callers` выдавал модули вместо функций; заметил это, сверив ответ с JSON из задания.
* `self` считался обычным параметром и ломал `self._wrap()` – ошибку помогли обнаружить тесты
* в ре-экспорте терялось импортируемое имя и `definition tiny_pkg.public_api` выдавал модуль вместо функции – обнаружил из тестов
